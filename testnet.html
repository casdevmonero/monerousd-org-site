Chain specifications

What you're running on. The numbers.

The testnet runs byte-for-byte production code. These are the real specs, measured on real nodes.

500 ms target Block time (mesh-wide, converges with producers)
32 parallel DAG width — blocks produced in parallel, ordered by GHOSTDAG
≤ 1.8 MB constant Recursive proof size — one proof covers the whole chain
O(1) always Node state — constant size regardless of chain height or note count

Node requirements

One kind of node. Runs on anything.

There are no tiers on MoneroUSD. Every node mines, verifies, proves and relays. A phone can run a full node.

Minimum hardware

CPU: Any 64-bit processor (x86-64 or ARM64). Mining hardware is proving hardware — no ASICs, no GPUs.

RAM: Under 512 MB. Node state is constant — the chain never grows your memory use.

Disk: Under 10 GB including the binary, Tor and data. No blockchain history to store.

Network

Transport: All traffic runs over Tor v3 onion services. The node bundles Tor — no setup needed.

Bandwidth: ~356 KB per payment (proof + block). Throughput is bounded by Tor bandwidth, not by the block cap.

Ports: No inbound ports required. The node reaches the network over Tor.

Software

OS: macOS (Apple Silicon), Linux (x86-64 or ARM64). Windows via WSL2.

Dependencies: None. The binary is self-contained and includes its own Tor client.

Sync: A new node checks one recursive proof and joins at the tip — no history replay.

What the testnet offers

The full ecosystem. Test value only.

Every feature runs on the testnet with the production code, byte-for-byte. The only difference: test coins instead of real money.

Private payments

Send and receive USDm with zero-knowledge proofs. Hidden amounts, senders, receivers and metadata. Post-quantum from the first byte.

Free test coins

Free test USDm on demand. Three taps in the wallet or one CLI command. Built into the node and locked to the testnet — cannot mint on mainnet.

Test bridge

Bridge test BTC (testnet4), test XMR (Monero testnet) and test ETH (Sepolia) through the real custody code. Native assets, no wrapping.

No risk

Test coins have zero value. The coin tap is locked to the testnet network: it cannot create real money, however you launch the node.

Usernames & Letter

Register a private username. Send encrypted messages with Letter. Try the full name system and private messaging layer.

Tap-to-pay

Point-of-sale payments over Bluetooth LE. Set up a merchant terminal, scan a code, tap your phone. The same UX as a contactless card.

Test coins only — no real funds at risk

  • The testnet coin tap prints free USDm on demand. These coins have zero real-world value.
  • The bridge connects to Bitcoin testnet4 and Monero testnet — test BTC and test XMR only.
  • The coin tap is locked to the testnet network: it is physically impossible for it to run on a mainnet chain.
  • The testnet may be reset at any time as the protocol evolves. Test balances do not survive a reset.
  • The production code is byte-for-byte identical — only the network identity differs. Every bug found here is a bug fixed before real money.
Get started

Three steps. Under five minutes.

Download the wallet

The MoneroUSD wallet runs the node for you. Download it, open it, and it connects to the testnet automatically.

macOS (Apple Silicon) Linux (AppImage)

Windows builds are coming. For now, run the CLI node on Windows via WSL2.

Get test coins

Open the wallet and tap Add money → Free test coins. Free test USDm arrives in seconds. You can also receive test BTC or test XMR through the bridge.

Send a payment

Tap Send, enter any testnet address or username, pick an amount. A zero-knowledge proof is generated on your device, broadcast to the network, and settled in seconds. Nobody — not even the nodes — can see the amount or the parties.

Install the node

One command. The install script verifies the binary, sets up Tor, and starts the node as a background service.

# macOS or Linux — downloads, verifies, installs curl -sSf https://monerousd.org/install-node.sh | bash

Or build from source:

# Clone and build git clone https://github.com/monerousd/monerousd-node-zkdag.git cd monerousd-node-zkdag cargo build --release --bin usdmd-node # Start the node on the testnet MONEROUSD_NET=testnet ./target/release/usdmd-node --port 27780

Get test coins

Hit the coin tap on your own node's RPC. The address is your wallet's receive address.

# Request test USDm from the built-in coin tap curl -X POST http://127.0.0.1:27780/tap/drip \ -H 'Content-Type: application/json' \ -d '{"amount": 100, "to": "YOUR_ADDRESS"}'

Run a validator

Bond test SAT to validate. The node derives its validator key from its own seed — no setup, no passwords.

# Start a validator (bonds SAT from a mined reward or the coin tap) MONEROUSD_NET=testnet MONEROUSD_VALIDATOR_BOND=1 \ ./target/release/usdmd-node --port 27780
What to expect

This is the production code

The testnet runs the exact same binary as mainnet — every consensus rule, every privacy guarantee, every hard fork activated at height 1. The only variable that changes is the network identity.

Resets happen

As the protocol evolves, consensus changes require a fresh start. Your test balances start over. The coin tap pays again immediately.

Bugs found here are bugs fixed

Every defect found on the testnet is fixed before real money touches the chain. Found something? Tell us on Telegram.
